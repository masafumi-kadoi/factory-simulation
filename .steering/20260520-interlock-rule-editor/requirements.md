# 要求内容

## 概要

FactoryVisualizerのローカルビュー（ロジック編集タブ）に、ステーションのインターロックルール（搬入可・搬出可などの信号ON/OFF条件）を視覚的に編集できるルールエディタを追加する。

## 背景

現在、搬入可・搬出可の信号条件はシミュレーションエンジン（Go）にハードコードされたデフォルト値のみで動作しており、ユーザーが工程の特性に合わせてカスタマイズする手段がない。バックエンドはすでに `config["interlockRules"]` フィールドを読み取ってデフォルトを上書きする仕組みを持つため、フロントエンドのUI追加のみで実現できる。

## 実装対象の機能

### 1. インターロックルール表示

- ローカルビューの「ロジック編集」タブに「インターロックルール」セクションを追加
- 対象ステーション種別: **processing / merge / split / switch**（source・drain・machine は対象外）
- ステーションを開いたとき、既存のカスタムルールがあればそれを、なければ**種別のデフォルトルールを初期値として**表示する

### 2. ルール編集UI

各ルールは以下の要素で構成:

| フィールド | UI | 説明 |
|---|---|---|
| ルールID | テキスト（自動採番・編集不可） | R1, R2, ... |
| 説明 | テキスト入力 | 任意のメモ |
| ターゲット信号 | ドロップダウン | 操作する信号名 |
| 設定値 | ON/OFFトグル | TrueにするかFalseにするか |
| 条件リスト | 条件行の追加・削除 | 複数条件はAND結合 |

各条件行:
- 信号名: ドロップダウン（ステーション種別に応じた選択肢）
- 期待値: ON/OFFトグル

### 3. ルール追加・削除

- 「＋ ルール追加」ボタンで空のルール行を追加
- 各ルール行に「削除」ボタン
- 各条件行にも「削除」ボタン、条件行内に「＋ 条件追加」ボタン

### 4. デフォルトに戻す

- 「デフォルトに戻す」ボタンをセクション上部に配置
- クリック時: 確認なしで config の `interlockRules` を削除し、デフォルトルールを再表示

### 5. 保存

- 既存の保存ボタン（ローカルビューの保存フロー）でルールも一緒に保存
- ルール内容は `config.interlockRules` に書き込む（バックエンドの既存仕組みに乗せる）

## 選択可能な信号名

ステーション種別ごとに異なるが、基本は以下の10信号:

```
inputWorkPresent, processingWorkPresent, outputWorkPresent,
running, complete, processReady, inputReady, outputReady,
workFull, workEmpty
```

merge は追加で `allPortsFull`、split は追加で `allPortsEmpty` を含む。

## 受け入れ条件

### ルール表示
- [ ] processing ステーションを開いたとき、デフォルトルール（R1〜R6）が表示される
- [ ] 保存済みカスタムルールがある場合はそちらが優先表示される
- [ ] source / drain ステーションではルールエディタセクションが表示されない

### ルール編集
- [ ] ターゲット信号・条件信号がドロップダウンで選択できる
- [ ] ON/OFFトグルが正しく動作する
- [ ] 条件行の追加・削除が正しく動作する
- [ ] ルール行の追加・削除が正しく動作する

### 保存・リセット
- [ ] 保存後、バックエンドが返すシナリオデータの config.interlockRules に編集内容が含まれる
- [ ] 「デフォルトに戻す」押下後、デフォルトルールが再表示されconfigのinterlockRulesが消える

## スコープ外

以下はこのフェーズでは実装しません:

- ポートレベルのインターロックルール編集（merge の入力ポートごと、split の出力ポートごと）
- 他ステーションの信号を条件に使う（`stationId` フィールドを使うクロスステーション条件）
- ルール評価シミュレーション（GUIで信号を手動操作して確認する機能）
- バックエンドのデフォルトルール取得API（JS側にデフォルトを定数として持つ）
